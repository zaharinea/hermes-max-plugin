# E2E-сценарии шлюза MAX

Матрица проверок, собранная по реальным диалогам владельца с Hermes в Telegram
(`state.db` на VM: 237 telegram-сессий) и по особенностям Bot API MAX.
Колонка «Авто» — где сценарий уже покрыт: **unit** (pytest в репозитории),
**live** (проверено на VM через web.max.ru), **manual** (ручная проверка).

## A. Базовый диалог

| # | Сценарий | Шаги | Ожидание | Авто |
|---|---|---|---|---|
| A1 | Текст в DM | Написать боту «привет» | Ответ агента в MAX, в логе `[max]` | live |
| A2 | Продолжение диалога | После ответа написать «ну что там?» | Тот же session_key, ответ учитывает контекст | manual |
| A3 | Команды gateway | `/status`, `/new`, `/reset`, `/stop` | Штатные ответы Hermes, сессия сбрасывается | manual |
| A4 | Незнакомец | Написать с чужого MAX-аккаунта | Молчание; `ignoring DM from user_id=…` в логе | unit |
| A5 | `/whoami` | Незнакомец пишет `/whoami` | Ответ с его `user_id`, не чаще cooldown | unit |
| A6 | Дубль update | Тот же `mid` приходит дважды | Один ответ (журнал дедупа) | unit |

| # | Сценарий | Шаги | Ожидание | Авто |
|---|---|---|---|---|

## H. Безопасность и эксплуатация

| # | Сценарий | Шаги | Ожидание | Авто |
|---|---|---|---|---|
| H1 | Токен | Проверить `.env`, логи, argv | Токена нет в репозитории и логах | live |
| H2 | TLS | Удалить CA и подключиться | Fatal `max_tls_failed` с инструкцией, без `verify=False` | unit/manual |
| H3 | Fail-closed | Пустой allowlist | Ни одно сообщение не проходит | unit |
| H4 | Rate limit | Серия быстрых ответов | ≤2/с на чат, общий лимитер | unit |
| H5 | Формат сообщения | HTML/plain переключатель | `MAX_FORMAT=plain` не ломает доставку | unit |

## Как гонять

- **unit**: `uv run --with pytest --with pytest-asyncio --with httpx python -m pytest -q` (тесты, требующие hermes, подхватываются при `HERMES_REPO=…`).
- **live**: web.max.ru в Chrome; для автоматизации — отдельный Chrome с `--remote-debugging-port=9222` и копией профиля (вход в MAX сохраняется), отправка через CDP `Runtime.evaluate` + `Input.dispatchKeyEvent`.
- **VM**: `hermes plugins validate/doctor <path>`, `tail -f ~/.hermes/logs/gateway.log | grep -i max`.

## Пробелы, которые стоит закрыть тестами

1. Контракт admission: `metadata` события обязана быть пустой (не-WhatsApp платформа) — уже покрыто регрессией.
2. Частичная отправка с медиа: вложение прикрепляется к первому чанку; при `partial_overflow` хвост идёт без вложения — нужен тест на «файл не потерян».
3. Маршрутизация `message_callback` с `update.user` — добавить фикстуру реального колбэка.
4. Голосовые: фикстуры «разреженного» `message_created` без `body`.
5. Формат `photos` в ответе `/uploads` для картинок — фикстура и терпимый парсер уже есть, теста нет.
